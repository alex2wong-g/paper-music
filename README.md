# 纸上音符

[中文](README.md) | [English](README.en.md)

一个复古风格的自动演奏钢琴网页应用。以暖白色界面、象牙色琴身与黄铜机械细节，呈现打孔纸卷驱动钢琴演奏的过程。导入 MIDI 或 MusicXML 乐谱，即可观看纸卷向下移动，并同步聆听音乐与观察琴键响应。

[在线体验](https://pianola-paper-and-sound.huangyixiu1.chatgpt.site/)

## 应用效果

![纸上音符 钢琴全景：暖白色界面、象牙色立式自动钢琴与打孔纸卷](docs/images/pianola-full-piano.png)

钢琴全景模式：完整呈现琴身、88 键键盘、纸卷机构与踏板。

![纸上音符 纸卷特写：带有复古纸张纹理的打孔卷轴及播放控制栏](docs/images/pianola-paper-roll.png)

纸卷特写模式：横向位置对应音高，孔的长度对应音符时值；播放时，纸卷随时间向下移动，经过读孔线的音符同步发声。

## 曲谱架

当前曲目信息旁的「曲谱架」可展开内置曲集。在暖白色浮层中搜索曲名或作曲家，按简短旋律、流动和声、节奏探索筛选，并查看开篇谱面、时长、起始 BPM、拍号与观察提示。翻阅时保留当前演奏；确认「载入此曲」后，所选乐谱从头待播。再次打开当前曲目可直接返回琴前，保留进度。

内置 12 份用户提供的 MusicXML 原谱：《致爱丽丝》《G 大调小步舞曲》《欢乐颂》《祝你生日快乐》《天鹅湖》《D 大调卡农》《月光奏鸣曲》第一乐章、肖邦《夜曲》Op. 9 No. 2、德彪西《月光》《土耳其进行曲》《匈牙利舞曲》第五号与《演艺人》。原文件位于 `public/scores/`，保留原谱的署名、编配与版权信息。卡片上的观察提示并非正式难度评级。

曲谱架支持中文 / EN、键盘与 Escape 关闭；手机上点选曲目后会移至详情，也可返回列表继续翻阅。谱面预览与正式五线谱使用同一渲染库，选定曲目同时支持打孔纸卷和五线谱演奏。

## 五线谱学习模式

在演奏区域右上角切换「打孔卷轴 / 五线谱」，即可查看纸质五线谱。谱面使用 [OpenSheetMusicDisplay](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay) 排版，保留 MusicXML 的双手谱表、升降记号、和弦、连线、反复记号和原谱指法。

- **跟随节拍列**：播放时高亮当前音符所在的纵列，跨越双手谱表；支持反复跳转、速度变化、拖动进度及自动滚动。
- **观察键位**：下方键盘与原琴键同步高亮。绿色提示左手谱表，金色提示右手谱表；暂停后可继续观察当前音符、琴键与指法，也可点击琴键试听。
- **慢速练习**：播放速度最低可调至 25%。「自动跟随」可切换为「自由浏览」，方便停留查看复杂段落。
- **按原谱指法学习**：MusicXML 带有指法标记时，谱面、当前音名与键盘会显示对应手指编号（1–5）。未标指法的乐谱仅显示键位，不自动推算指法；左右手提示根据谱表和谱号分组，不处理交叉手等演奏技巧。

MIDI 不含原始五线谱拼写或指法。其五线谱由音符转换生成，节奏量化到十六分音符，左右手以中央 C 为音域分界推测；这不会改变原始 MIDI 的声音时序。复杂节奏、声部与指法学习请使用 MusicXML，以保留原谱信息。

## 功能

- **中英切换**：默认中文，右上角可切换 EN；BPM、MIDI、MusicXML 等专业术语保持原文。界面字号为 13–38px，站名不超过 38px。

- **两种镜头**：钢琴全景与纸卷特写，支持平滑切换。
- **复古视觉**：2.5D 立式钢琴、带纤维与旧化痕迹的纸张、黄铜卷轴，以及完整的 88 键键盘。
- **默认示例**：内置完整《致爱丽丝》MusicXML 乐谱，与导入文件使用同一套解析流程。
- **乐谱导入**：支持 MIDI（`.mid`、`.midi`）、MusicXML（`.xml`、`.musicxml`）和压缩 MusicXML（`.mxl`），可选取文件或拖放导入。
- **同步演奏**：纸卷移动、合成音色与琴键高亮使用同一条时间轴。
- **五线谱显示**：按需加载专业渲染引擎，支持节拍列高亮、自动跟随、原谱指法和可试听的学习键盘。
- **播放控制**：播放、暂停、拖动进度、回到开头、调节速度、音量与静音；支持空格键切换播放状态。
- **本地处理**：乐谱文件在浏览器内解析，无需上传到服务器。
- **适配与交互**：响应式布局、键盘操作与减少动态效果偏好支持。

## 本地运行

需要 Node.js 和 npm。在仓库根目录执行：

```sh
npm ci
npm run dev
```

打开终端中显示的本地地址。

## 构建与部署

```sh
npm run build
```

构建结果位于 `dist/`，可部署到静态网站托管服务。`.openai/hosting.json` 保留了本项目现有的 Sites 发布配置。

### GitHub Pages

在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。推送到 `main` 后，`.github/workflows/pages.yml` 会安装依赖、构建并发布 `dist/`。

工作流根据 Pages 配置自动设置 Vite 的 `base`；本仓库的项目路径为 `/paper-music/`，构建后的 JS、CSS 和曲谱均从此路径载入。不要选择直接发布 `main / (root)`，源码中的 `/src/main.js` 是开发入口，需要由 Vite 转换为构建资源。

本地模拟项目路径构建：

```sh
npm run build -- --base=/paper-music/
npx vite preview --base=/paper-music/
```

普通 `npm run build` 仍使用根路径，适用于现有 Sites 托管。

## 乐谱解析与播放范围

MIDI 保留音符起止时间、力度及速度变化，并排除打击乐轨道。MusicXML 支持时值单位、休止符、和弦、多声部、声部时间回退与前进、速度变化、移调、延音线、反复记号及不同结尾。

当前限制：

- 使用浏览器本地合成的钢琴近似音色；尚未使用原声钢琴采样，也未模拟真实气动机构。
- MusicXML 需使用 `score-partwise` 格式。
- 暂不演奏倚音和装饰音，不解析 D.C.、D.S.、Coda 跳转及踏板标记。
- 仅演奏 A0–C8 范围内的 88 键音符。
- 浏览器标签页切换到后台时自动暂停。

## 验证

`qa/browser-check.js` 提供浏览器验证函数，覆盖默认乐谱、88 键布局、MIDI 速度变化、MusicXML 多声部与延音线、反复及不同结尾、MXL 解压、无效文件处理、文件导入及播放控制。启动开发服务器后，可通过浏览器脚本执行该函数。

`qa/sheet-check.js` 验证五线谱排版、原谱反复、速度变化、双谱表游标、暂停后键位显示、指法标记、MIDI 转谱与模式切换。

`qa/shelf-check.js` 验证 12 份曲谱的解析与开篇预览、搜索和分类、快速切换、不中断当前演奏、载入归零、中英切换及五线谱模式。
